Routing (v18g: pitch→LPC now requires SOLO content type):
  hasFormant (|formantShift| > 0.5 st)              → LPC source-filter
  hasPitch AND SOLO AND voiced speech (2 kHz bp)    → LPC source-filter
  else                                               → Phase Vocoder
  (chord = BACKING content; its blocks were transiently passing the per-block
   2 kHz check and routing to LPC — SOLO gate fixed chord_Cmaj_pitch_up7st)
  LPC min guard order = 8 when voiced AND (hasFormant OR hasPitch) (else 2)

Pre-emphasis logic (Sessions 13-14, the v18 series):
  H(z) = 1 - 0.97z^-1 applied to LPC analysis frame. v18h: DUAL OLA STREAMS --
  pre-emphasised frames OLA into outputBuffer_ (de-emphasised continuously at
  read time); bypassed frames OLA into outputBufferPlain_ (read as-is); summed
  per sample at output. Direction-aware bypass:
    formantUpBypass: voiced AND formant shift >= 0 (v18h: now includes speech)
      -> use plain frame. Pre-emph distorts upward pole shifts
      (sine_440_formant_upmax: 32.8 plain vs 13.7 pre-emph, old metric;
      vocal_aah_formant_upmax recovered to 34.5 once dual streams removed the
      cross-tilt), but helps downward shifts -> keep pre-emph for those.
    largePitchDown: voiced AND no formant shift AND pitch < -6 st
      -> use plain frame (vocal_aah_pitch_down12st 27.0 plain vs 19.9 pre-emph,
      old metric); upward pitch keeps pre-emph (vocal_aah_pitch_up7st 24.9 vs 19.0).
    polyphonicContent (VariphraseParams flag, set by Hybrid routing for
      ENSEMBLE/BACKING): bypassed frames route into the DE-EMPH stream anyway --
      chord formant empirically wants the low-shelf tilt (21.2 tilted vs 17.9
      clean vs 19.8 pre-emph, old metric).
  DO NOT fold de-emphasis into the LPC polynomial (A(z)*(1-0.97z^-1)): order
  P+1 truncated to P distorts ALL formant roots (v18d failure).
  DO NOT de-emphasise per-frame with fresh state (v18 experiment, 27.0):
  the integrator needs cross-frame state at F0 ~ 120 Hz; dual streams with
  continuous state per stream is the working design.

SOLO encoder (v39): plugin/Source/XtSoloEncoder.cpp needs one table from the
  user's XT firmware image — set VSE_XT_ROM=<path to V-SynthXT.rom.2.bin> or
  keep the unpacked copy at firmware/unpacked/ (gitignored; the renderer looks
  there relative to the working directory). Without it the v38 epoch encoder
  is used. VSE_ENC=epoch|vt forces the older encoders.
  Stereo sources: the XT encodes (L+R) >> 1, so the engine floors its int16
  conversion of the 0.5·(L+R) mono input; `xt_encode rom samp.bin stereo`
  takes interleaved L/R.

BACKING / ENSEMBLE players (2026-10-28): plugin/Source/XtMultiBandPlayer.cpp,
  bit-exact against the firmware players run in the P-code emulator. Like
  the SOLO encoder it reads its tables from the user's rom.2 at run time.
  Not wired into the engine yet: it needs the load-time band data and the
  vpdt, which come from the multi-band encoder (not ported). Validation CLI:
    clang++ -std=c++20 -O2 -ffp-contract=off -DXT_MBPLAYER_MAIN \
      plugin/Source/XtMultiBandPlayer.cpp -o xt_mbplay
    xt_mbplay rom.2.bin vpdt.bin mem.samp b1,..,b5 <ch> out.f32 <pitch> <walk>
  (inputs as research/ghidra_scripts/EmuBacking.java; XT_MODE=5 ENSEMBLE,
  XT_ROUND=nearest to match the emulator's rounding).
    xt_mbplay rom.2.bin --bands samp.bin <ch> out.samp
  rebuilds a BACKING wave's band data (xtMbBuildBacking) as the XT's sample
  memory and prints the band addresses, for comparison with EmuLoad.java.

F0 ESTIMATION (v19b/c, SourceFilterModel::estimateF0):
  - NO pre-emphasis in estimateF0 (v19c): it boosts formants and on speech the
    F1-region ACF peaks (~600 Hz) beat the fundamental — F0 flapped 130<->600 Hz
    and pitch shifts rendered a fourth sharp. ACF pitch detection wants the
    fundamental dominant (the opposite of LPC analysis needs).
  - frame reaching ACF is Hann^2-tapered (windowed twice); winAcf_ (ACF of w^2,
    precomputed in prepare) unbiases it. Correction clamped at 2.0 (diverges at
    long lags -> spurious peaks).
  - OCTAVE GUARD: only integer subharmonics of the global max (lag/2,/3,/4,
    +-2 samples) qualify as shorter-lag candidates; a looser "any local max
    within 5%" rule picked formant sub-peaks at non-integer fractions.
  - Verified output fundamentals: sine cases 441.0 Hz (target 440); vocal
    pitch+7 190.5 Hz (target 195.9).

PATENT FINDINGS (Session 15, research/PATENTS.md — READ THIS FIRST):
  US6421642B1 (Roland, filed 2000-05) IS VariPhrase. The real SOLO algorithm
  is PITCH-SYNCHRONOUS GRANULAR, not LPC:
    encode: cut phrase into ~1-pitch-period grains, store per-grain pitch
            (cwp) + syllable marks (= our event stamps)
    time   = rate of walking the grain list (tcv)
    pitch  = grain re-trigger period ppw = cwp x pitchRatio; TWO channels,
             half-cycle offset, triangular windows
    formant= grain READ VELOCITY fsv (resample grain content);
             window length = cwp/fsv CLAMPED <= ppw (explains our measured
             ~0.75x upward saturation mechanistically)
  US6564187B1: multiband subband time stretch — the ENSEMBLE/BACKING path.
  US6201175B1: band-wise sinusoidal modelling variant.
  Our LPC source-filter path approximates grain resynthesis; black-box was
  directionally right, mechanistically wrong.

Subband/granular A/B results (Session 15, do not re-run):
  - granular on ENSEMBLE: chord_time 31.5, chord_pitch 36.7 — worse than PV;
    pitch-sync cutting unsuitable for polyphony (why Roland filed US6564187).
  - subband on BACKING: drum_halfspeed 38.1 (worse than event-based 49.6 —
    trajectory resampling smears transients), drum_time_2x 54.9 (+3.0 vs
    event-based) — not adopted (one-case marginal; idea queued below).
